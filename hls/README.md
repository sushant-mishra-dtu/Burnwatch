# hls/

The PL tile engine in Vitis HLS. It matches [`detector/golden.py`](../detector/golden.py) (spec v1, FULL mode: 1280×720, 16×16 tiles) bit for bit in C simulation. Interface: [`docs/contracts.md`](../docs/contracts.md) section 7.

| File | What it is |
|---|---|
| `tile_engine.cpp`, `tile_engine.h` | The core: one pass over the frame at one pixel per clock, then per tile row a short loop for means, score, changed count and baseline update |
| `tb_tile_engine.cpp` | C testbench: replays golden vector sets and compares scores, gate, changed and frame_count exactly |
| `run_hls.tcl` | csim → csynth → `export_design -format ip_catalog` |
| `config.h` | Generated by `python tools/gen_header.py` from `detector/config.py` (geometry + testbench defaults) |
| `reports/csim_result.txt` | The C-simulation result quoted below |
| `reports/csynth.rpt` | The synthesis summary quoted below |

## Run it

Vitis HLS 2022.1 ships `vitis_hls` (not `vitis-run`). From the repo root on Windows (PowerShell):

```powershell
python tools/dump_golden.py --synthetic
python tools/dump_golden.py --synthetic --update-every 3 --reset-at 0,30 --name synthetic-u3
python tools/dump_golden.py --synthetic --name synthetic-regs --param K_SLOW=2 --param K_FAST=3 --param W_EDGE=200 --param W_GREY=17 --param SCORE_SHIFT=5 --param T_FLAG=20 --param SAT_MAX=60 --param SAT_TOL=300 --param T_GLOBAL=2000 --param GATE_TILES=1000
& 'M:\amd_xilinx\Vitis_HLS\2022.1\bin\vitis_hls.bat' -f hls\run_hls.tcl
```

- `BW_HLS_STEPS` picks steps (default `csim csynth export`), and `BW_GOLDEN_SETS` picks vector sets (default the three synthetic sets above). Add clip sets made with `tools/dump_golden.py --clip`.
- Vitis HLS refuses project paths with a space. When the repo path has one, the project goes to `burnwatch_hls/` at the root of the repo's drive (override with `BW_HLS_WORK`). The exported IP is `<work>/tile_engine_prj/sol1/impl/export.zip`.
- C simulation takes about 2 minutes per 40-frame set. For quick iteration, compile the same sources natively: `g++ -O2 -I hls -I <Vitis_HLS>/include hls/tile_engine.cpp hls/tb_tile_engine.cpp` (about 4 s per set).

## Results (11 Oct 2026, Vitis HLS 2022.1, xc7z020clg400-1, 10 ns clock)

**C simulation: bit-exact.** 5 vector sets, 200 frames, 720,000 tile scores, 0 mismatches in scores, gate, changed or frame_count ([`reports/csim_result.txt`](reports/csim_result.txt)):

| Set | What it covers |
|---|---|
| `synthetic` | Default registers; smoke plume, saturated block, walking person; frame 20 gated |
| `synthetic-u3` | `update_this_frame` only every 3rd frame; a second reset at frame 30 |
| `synthetic-regs` | Every register non-default; frames 20–22 gated, so `k_fast = 3` is used; scores clip at 255 |
| `clip-20261011_102856`, `clip-20261011_102913` | Two recorded 4K phone clips, resized to 1280×720, every 3rd frame |

Injecting a one-character bug (the baseline rounding term, or the last-column edge flush) makes the testbench fail with per-tile mismatches, so a pass is meaningful.

**Synthesis estimate** ([`reports/csynth.rpt`](reports/csynth.rpt)). These are HLS estimates, not measured board numbers:

| Metric | Value |
|---|---|
| Pixel loop `COLS` | II = 1 |
| Tile loop `TILES` | II = 1 |
| Latency per frame | 1,007,464 cycles = 10.07 ms at 100 MHz (≤ 1.66 M cycle target for 60 fps) |
| Estimated clock | 7.30 ns (target 10 ns) |
| BRAM_18K / DSP / FF / LUT | 20 (7%) / 4 (1%) / 4,605 (4%) / 8,043 (15%) |
| AXI | frame read in 1,280-word row bursts on `gmem0`; 80-byte score bursts on `gmem1`; 32-bit addresses |

Register offsets are in the generated `xtile_engine_hw.h` and in `reports/csynth.rpt` (`frame` 0x10, `scores` 0x18, `reset` 0x20 … `gate_tiles` 0x78; outputs `gate_out` 0x80, `changed_out` 0x90, `frame_count` 0xa0).
